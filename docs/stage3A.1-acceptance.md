## Что изменилось

Единый монитор показывает тип операции, ID, начало, длительность, последний
подтверждённый прогресс, этап, доступные признаки процесса/CPU и итог. Состояние Git
и результаты TEST разделены. Короткие пояснения заменили длинную диагностику.
Автоопрос перенесён на уровень Activity, поэтому переход в журнал его не выключает.
Ручная проверка прежнего ID видна при задержке подтверждения либо UNKNOWN.
Один pending transport сериализует авто/ручной QUERY и чтение журналов.

Настройка предупреждения: 5/10/15/20/30 минут, по умолчанию 10. Она не прерывает
процесс. «Продолжить ждать» сохраняет следующий срок предупреждения, не вызывает
START. Жёсткий предел TEST — 90 минут, Git-лимиты не менялись. При возможных
оставшихся JVM — UNKNOWN и блокировка повторного запуска.

Журнал «Важное» / «Всё»: история AnimaDev, реальные команды, stdout/stderr,
этапы, результаты, JUnit, exit и длительность. Чтение порциями примерно 6 KiB,
курсор и страницы сохраняются в отдельной Android SQLite, не мегабайтных
SharedPreferences. Длинный текст отображается лениво блоками. Есть поиск по
загруженному тексту, выделение и копирование фрагмента, копирование всего выбранного
режима, экспорт в Downloads через MediaStore (Android 29+), SAF на 26–28.
Журнал текущего RUNNING обновляется автоматически, остальные — по кнопке.
Последний режим, выбранное задание и позиция просмотра сохраняются.

Runner добавляет events/journal_meta к прежней SQLite без удаления jobs.
Журнал очищается до записи и сохраняется независимо от Activity. Предел 5 MiB
на задание явно отмечается; вычисление и итог продолжаются после исчерпания лимита.
100 заданий остаются лимитом, автоматической очистки нет. Старые immutable runner
сохраняются, старое выполняющееся задание запрашивается своим SHA/протоколом.
Ограниченный вывод прежних версий показан с пояснением: полного старого журнала
никогда не существовало, его нельзя восстановить задним числом.

Уведомления отражают подтверждённое Android-состояние и открывают журнал Job ID.
Разрешение Android 13+ доступно в настройках; отказ не блокирует операции.
Foreground service не добавлялся. При закрытом или force-stopped AnimaDev итоговое
уведомление может прийти только после открытия и QUERY; runner всё равно хранит
результат. Уведомление не гарантирует, что Android сохранит Termux/JVM в памяти.

Кнопки отмены нет. Только технический проект будущей 3А.2:
[stage3A.2-cancellation-design.md](stage3A.2-cancellation-design.md).

## Что ещё не проверено на Android 0.3.1

Реальные поворот, закрытие Activity, force-stop, авария UI, перезапуск устройства,
системное разрешение уведомлений, экспорт MediaStore/SAF, выбор/поиск/копирование
в журнале, отсутствие визуального мерцания и обновление поверх установленной версии.
На 0.3.0 владелец уже подтвердил 396/396 и сохранение результата; это не является
Android-приёмкой новой версии. Реальный SYNC с новыми коммитами по-прежнему не принят.

CPU и /proc доступны не на всех Android: недоступность показана явно.
Наблюдаются контролируемый процесс и доступные прямые дети; отдельные/глубокие JVM
могут не дать показателей. Молчание само по себе не доказательство зависания.
Частичная незавершённая строка остаётся в RAM и может потеряться при смерти runner.
Фильтрация консервативная для известных форматов и блоков авторизации; обнаружение
любого неизвестного секрета без признаков его формата не обещается.

## Приёмка только через интерфейс

1. Открыть APK в «Загрузках» и обновить AnimaDev поверх установленного приложения.
   Проверить прежние результаты TEST и Git. Не удалять приложение и не очищать данные.
2. Если предлагается «Настроить локальный помощник», подтвердить кнопку. Старое
   незавершённое задание сначала должно получить итог; его нельзя запускать повторно.
3. В «Настройки» выбрать 5 минут, вернуться и снова открыть настройки: выбор сохранён.
   При желании разрешить уведомления. Проверить, что отказ не блокирует TEST.
4. В AnimaQuiz нажать «Запустить тесты». Видны ID/начало/время/этап; Git заблокирован
   с понятной причиной. При нормальном ответе ручная проверка состояния не мигает.
5. «Открыть журнал»: переключить «Важное»/«Всё», дождаться загрузки, найти текст,
   выделить фрагмент, скопировать всё и сохранить в Downloads. В журнале настоящая
   команда Gradle, новые строки появляются во время выполнения.
6. Повернуть экран; затем «Назад» → «Выйти». Открыть AnimaDev снова: прежний ID,
   действительное состояние и сохранённый журнал, повторного TEST нет.
7. Отдельно проверить системную принудительную остановку AnimaDev во время TEST,
   затем открыть. Runner продолжает независимо; QUERY восстанавливает прежний ID,
   доступные логи и итог JUnit. Не останавливать Termux для обычной приёмки.
8. После итогового TEST проверить количество и exit code, закрыть/открыть снова,
   выбрать это задание в истории. При отсутствии подтверждённого прогресса дольше
   выбранного порога: предупреждение, «Продолжить ждать» сохраняет тот же ID;
   «Открыть журнал» не запускает тесты повторно. Если CPU растёт, предупреждения
   может не быть — это ожидаемый подтверждённый признак вычисления.
9. Если появляется UNKNOWN, нажать «Проверить состояние задания». Проверяется
   прежний ID, START не повторяется; новые конфликтующие действия остаются закрыты
   до доказанного итога.

После передачи этой версии работа остановлена до Android-приёмки владельцем.
