# Архитектура AnimaDev

## Основа этапа 2.1

Один фиксированный профиль AnimaQuiz. Android UI → короткий RUN_COMMAND →
проверенный по SHA-256 локальный runner → задания SQLite → существующий Git/SSH
Termux. Никакого серверного компонента в установленном приложении нет.
Только STATUS/CHECK/SYNC, фиксированный каталог, branch и origin; SYNC ff-only
с повторной проверкой чистоты и локального HEAD. Новых токенов или паролей в APK нет.

Задание и короткий транспортный запрос имеют разные ID. Потеря callback не
означает успех и не допускает повторного START. UNKNOWN опрашивается по ID.
Выход закрывает Activity и убирает task через finishAndRemoveTask(), не завершает
процессы Android/Termux. Диалог и выбранный экран сохраняются при повороте.
Данные SharedPreferences и SQLite не очищаются при выходе или обновлении APK.

Runner обновляется отдельной кнопкой с проверкой встроенных байтов и SHA.
Старые immutable releases не удаляются. Незавершённый job опрашивается через
его runner SHA, а для записей 0.2.0 без SHA используется известная release-копия.
Версия ответа проверяется относительно выбранного транспорта. После завершения
старого задания UI предлагает обновить помощник; новый START использует новый
runner. Это сохраняет результаты и исключает случайный повтор SYNC при обновлении.

Ошибка fetch имеет реальный exit code и фиксированную понятную категорию:
DNS, сеть, SSH-авторизация, SSH host key, доступ к репозиторию/ветке, прочая ошибка.
Классификация эвристическая по ограниченной диагностике Git при LC_ALL=C;
неизвестная диагностика не копируется в пользовательское сообщение.
Сырые stderr Git и JSON с вложенными диагностическими логами не отображаются.
Повтор CHECK разрешён только отдельным нажатием после terminal FAILED,
через обычные проверки профиля. Автоматического SYNC нет.

## Будущие требования — не реализовывать на этапе 2.1

- AnimaDev работает с одним существующим GitHub-аккаунтом владельца. Поддержка
  нескольких аккаунтов не нужна. SSH Termux остаётся локальным способом доступа.
- Кнопка «+» предлагает список локальных Git-репозиториев Termux. Уже открытые
  проекты исключены по стабильному project ID и каноническому каталогу.
- Выбор открывает отдельную вкладку проекта с собственными настройками профиля,
  текущим состоянием, журналом и ID заданий. Данные и блокировки разделены по project ID.
- Разные проекты смогут работать независимо; в одном проекте одновременно
  разрешено только одно Git-задание. Допуск параллельности потребует отдельной проверки.
- Закрытие вкладки убирает только представление проекта; репозиторий и файлы
  Termux не удаляются, незавершённое задание не отменяется и остаётся доступным
  для восстановления при повторном открытии проекта.
- В будущем добавить поиск публичных GitHub-репозиториев, клонирование в Termux
  по выбору или ссылке, а также создание fork в единственном аккаунте владельца.
  Clone и fork — разные явные операции; сам clone не создаёт fork на GitHub.
- Расширение требует проверенных каталогов/origin/веток, безопасного разрешения
  имён, сохранения запретов main и разрушительных Git-операций. Команды из файлов
  репозиториев не исполняются. Новые токены и пароли в APK не хранятся.
- Права для будущего fork/API и способ их получения согласовываются отдельным
  этапом; текущий APK не получает дополнительных сетевых или аккаунтных функций.

Сейчас нет «+», нескольких вкладок проектов, поиска, clone/fork или тестов и
сборок QuizApp. Эти требования не являются разрешением начать следующий этап.

## Этап 3А: unit-тесты одного проекта

TEST использует ту же очередь, ID, SQLite и project-lock, что Git. Только
фиксированная команда `bash ./gradlew :app:testDebugUnitTest --offline
--no-daemon --rerun-tasks --console=plain` в проверенном ~/quizapp. Ветка и origin
проверяются перед стартом; main запрещён. Wrapper и Gradle-скрипты проекта
выполняются как необходимая часть согласованного тестирования; README/AGENTS
и пользовательские команды не исполняются. Исходники runner не изменяет.
Gradle может обновлять build/, .gradle/ и существующий кеш; тестируется текущее
рабочее дерево, включая незакоммиченные изменения. Не выполнять внешний Git/Gradle
параллельно с AnimaDev.

Модуль gradle_tests.py входит в APK и immutable release; его SHA записан в
проверенном основном runner. Загружаются и исполняются только совпадающие байты.
Предыдущие release 0.2.0/0.2.1 сохраняются для QUERY незавершённых Git-заданий.
Успех TEST — exit 0, свежие JUnit XML и failed 0. Нет отчётов — не успех.
Перед стартом фиксируются inode/mtime/ctime/SHA отчётов. После завершения
читаются только изменившиеся или новые TEST-*.xml; старые файлы игнорируются.
Проверяются тесты/кейсы/failure/error/skipped, конечность времени, согласованность
счётчиков. Запрещены DTD/entities и symlink; лимиты 500 XML, 2 MiB на файл,
8 MiB суммарно. Время JUnit — сумма suite time, время операции — фактический
интервал задания; это разные значения.

Логи потоково читаются без неограниченного накопления: 4096 символов на канал
SQLite, 1500 на канал callback; длинные строки свыше 8192 байт отбрасываются, остаток канала скрывается
для защиты от частично обрезанного секрета; многострочные ключи подавляются,
распознаваемые секреты маскируются, кадры трассировок удаляются. Диагностика
доступна в раскрываемом разделе. Последнее TEST сохраняется отдельно в prefs
и остаётся видимым после следующей Git-операции; полные задания хранятся SQLite.

Таймаут TEST 1200 с. Собственная группа основного Gradle-процесса останавливается;
--no-daemon может создавать отдельную одноразовую JVM, поэтому timeout или потеря
контроллера оставляют UNKNOWN с запретом любых новых операций проекта. QUERY
не запускает тесты заново и не снимает эту блокировку без подтверждения.
Автоматического сброса UNKNOWN в данной версии нет; такой редкий случай требует
отдельной проверки состояния, а не очистки истории или слепого повтора.

Будущая навигация: «Мои проекты» как основной экран и «Диагностика» как
вспомогательный. Диагностика Termux не должна выглядеть обязательным первым
шагом каждого действия. В этапе 3А добавлены только пояснения назначения
кнопок, повторов и блокировок; полный редизайн, дополнительные проекты и
сборка APK QuizApp не реализуются.

## Монитор и журнал 3А.1

Runner 0.3.1 использует прежнюю jobs.sqlite3 и добавляет таблицы events и
journal_meta без удаления jobs. Существующие immutable releases сохраняются:
незавершённое старое задание запрашивается его прежним runner/SHA. После его
завершения новый помощник устанавливается отдельной кнопкой. Исторические
ограниченные хвосты доступны с явным предупреждением: полного старого вывода
не существовало, восстановить его нельзя.

Команда TEST фиксирована, защитный предел 90 минут. stdout/stderr очищаются
потоковым фильтром до постоянной записи. Частичная строка буферизуется в памяти;
при аварии её остаток может быть потерян. Слишком длинная строка закрывает канал
для защиты секретов. Блоки ключей и авторизации подавляются консервативно,
включая продолжение строк. Нельзя обещать обнаружение любого неизвестного
формата секрета без признаков авторизации.

События сохраняются постепенно; лимит 5 MiB прекращает добавление вывода,
но не выполнение и не обновление результата. Прежняя история не удаляется.
Лимит 100 заданий остаётся: будущая архивация потребует отдельного согласования,
экспорта с проверкой целостности и явного управления владельцем.

Фиксированные read-only режимы HISTORY и LOG читают только зарегистрированный
проект и валидированные Job ID/смещение/вид. Страницы ограничены ~6 KiB.
Android хранит страницы и курсор в собственной SQLite, настройки — отдельно.
QUERY/START/LOG/HISTORY используют один pending transport; nonce отклоняет
поздние ответы. Центральный опрос живёт на уровне Activity, независимо от экрана.
После открытия запрашивается прежний ID, никогда повторный START.

Последний прогресс обновляют содержательный вывод, реальные изменения XML и
доступный рост CPU-time проверенного процесса/прямых детей. /proc может быть
ограничен Android; недоступные признаки не заменяются выдуманными значениями.
Состояние «жив» отдельно от «вычисляет». Обычный опрос не сбрасывает предупреждение.
Продолжить ждать сохраняет срок следующего предупреждения для того же задания.
Смерть контроллера TEST или неопределённый остаточный daemon — UNKNOWN.

Уведомления не требуют foreground service. Они обновляются при получении
подтверждённого состояния Android, открывают журнал нужного ID, не гарантируют
фоновое получение итога при закрытом/force-stopped приложении. Termux сохраняет
итог независимо; при открытии QUERY восстанавливает его и обновляет уведомление.
Отказ в POST_NOTIFICATIONS не блокирует задания. Foreground service Android 15
для этого механизма не нужен и не внедряется.

Навигация в будущей переработке: «Мои проекты» как основной экран,
«Диагностика» вспомогательный. Сейчас только связанные монитор/журнал/настройки.
