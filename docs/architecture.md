# Архитектура AnimaDev

## Текущий этап 2.1

Один фиксированный профиль AnimaQuiz. Android UI → короткий RUN_COMMAND →
проверенный по SHA-256 локальный runner → задания SQLite → существующий Git/SSH
Termux. Никакого серверного компонента в установленном приложении нет.
Только STATUS/CHECK/SYNC, фиксированный каталог, branch и origin; SYNC ff-only
с повторной проверкой чистоты и локального HEAD. Новых токенов или паролей в APK нет.

Задание и короткий транспортный запрос имеют разные ID. Потеря callback не
означает успех и не допускает повторного START. UNKNOWN опрашивается по ID.
Выход закрывает Activity и убирает task через finishAndRemoveTask(), не завершает
процессы Android/Termux. Диалог и выбранный экран сохраняются при повороте.
Данные SharedPreferences и SQLite не очищаются при выходе или обновлении APK.

Runner обновляется отдельной кнопкой с проверкой встроенных байтов и SHA.
Старые immutable releases не удаляются. Незавершённый job опрашивается через
его runner SHA, а для записей 0.2.0 без SHA используется известная release-копия.
Версия ответа проверяется относительно выбранного транспорта. После завершения
старого задания UI предлагает обновить помощник; новый START использует новый
runner. Это сохраняет результаты и исключает случайный повтор SYNC при обновлении.

Ошибка fetch имеет реальный exit code и фиксированную понятную категорию:
DNS, сеть, SSH-авторизация, SSH host key, доступ к репозиторию/ветке, прочая ошибка.
Классификация эвристическая по ограниченной диагностике Git при LC_ALL=C;
неизвестная диагностика не копируется в пользовательское сообщение.
Сырые stderr Git и JSON с вложенными диагностическими логами не отображаются.
Повтор CHECK разрешён только отдельным нажатием после terminal FAILED,
через обычные проверки профиля. Автоматического SYNC нет.

## Будущие требования — не реализовывать на этапе 2.1

- AnimaDev работает с одним существующим GitHub-аккаунтом владельца. Поддержка
  нескольких аккаунтов не нужна. SSH Termux остаётся локальным способом доступа.
- Кнопка «+» предлагает список локальных Git-репозиториев Termux. Уже открытые
  проекты исключены по стабильному project ID и каноническому каталогу.
- Выбор открывает отдельную вкладку проекта с собственными настройками профиля,
  текущим состоянием, журналом и ID заданий. Данные и блокировки разделены по project ID.
- Разные проекты смогут работать независимо; в одном проекте одновременно
  разрешено только одно Git-задание. Допуск параллельности потребует отдельной проверки.
- Закрытие вкладки убирает только представление проекта; репозиторий и файлы
  Termux не удаляются, незавершённое задание не отменяется и остаётся доступным
  для восстановления при повторном открытии проекта.
- В будущем добавить поиск публичных GitHub-репозиториев, клонирование в Termux
  по выбору или ссылке, а также создание fork в единственном аккаунте владельца.
  Clone и fork — разные явные операции; сам clone не создаёт fork на GitHub.
- Расширение требует проверенных каталогов/origin/веток, безопасного разрешения
  имён, сохранения запретов main и разрушительных Git-операций. Команды из файлов
  репозиториев не исполняются. Новые токены и пароли в APK не хранятся.
- Права для будущего fork/API и способ их получения согласовываются отдельным
  этапом; текущий APK не получает дополнительных сетевых или аккаунтных функций.

Сейчас нет «+», нескольких вкладок проектов, поиска, clone/fork или тестов и
сборок QuizApp. Эти требования не являются разрешением начать следующий этап.
