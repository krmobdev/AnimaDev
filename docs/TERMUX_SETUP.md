# Termux — подготовка для AnimaDev

[English](TERMUX_SETUP_EN.md) · [Главная](../README.md) · [Сборка самого AnimaDev](BUILD_FROM_SOURCE.md)

**Сначала:** Termux нужен для выполнения локальных Git- и Gradle-команд из AnimaDev. Для обычных Git/Gradle-функций **не требуются** AnimaBridge Agent, Shizuku, VPS или отдельный сервер. Устанавливайте необходимые инструменты самостоятельно; AnimaDev не загружает системные пакеты молча.

## 1. Установить Termux и разрешить управление

1. Установите совместимый Termux из доверенного источника и откройте его хотя бы раз.
2. В Termux выполните `mkdir -p ~/.termux` и добавьте строку `allow-external-apps=true` в `~/.termux/termux.properties` (сохраняя остальные настройки).
3. Примените настройки Termux и в Android выдайте AnimaDev разрешение `com.termux.permission.RUN_COMMAND`, когда будет запрос. На некоторых версиях Termux потребуется повторно открыть приложение.
4. В AnimaDev откройте **Termux → Проверить окружение**. Запуск проверки сам по себе не должен устанавливать новые пакеты.

`RUN_COMMAND` предоставляет приложению право выполнять разрешённые команды от имени пользователя Termux. Выдавайте это разрешение **только доверенным приложениям**.

## 2. Базовые инструменты

Откройте Termux и выполните вручную:

```sh
pkg update
pkg install git python openjdk-21 curl unzip
```

Проверьте `java -version`, `git --version`, `python --version`. Доступ к общему хранилищу может потребовать `termux-setup-storage` и подтверждения Android; используйте его только при необходимости.

Git-репозитории должны уже находиться в доступном для Termux каталоге. Настройку GitHub SSH выполняйте локально; закрытые ключи и токены не добавляйте в Git.

## 3. Android SDK и Gradle

Для Android-сборок нужен полноценный **Android SDK** (platform-tools, Platform под `compileSdk` проекта и совместимые build-tools) плюс Java. Установить только JDK **недостаточно**.

Для сборки **самого AnimaDev** актуален **Android SDK Platform 37**, JDK 21, Gradle wrapper 9.5.0 и AGP 9.3.1. Для других проектов руководствуйтесь **их** `build.gradle.kts`.

Укажите фактический путь к SDK; пример для каталога `~/android-sdk`:

```sh
export ANDROID_HOME="$HOME/android-sdk"
export ANDROID_SDK_ROOT="$ANDROID_HOME"
```

**Важно для Termux:** стандартный настольный AAPT2 может не запускаться на Android. При необходимости установите совместимый Termux AAPT2 и укажите Gradle-override `-Pandroid.aapt2FromMavenOverride=/полный/путь/к/aapt2`. Это зависит от окружения, не используйте путь вслепую.

Используйте wrapper конкретного проекта:

```sh
./gradlew --version
./gradlew :app:testDebugUnitTest :app:assembleDebug --no-daemon --console=plain
```

Для первой сборки **не добавляйте `--offline`**, иначе Gradle не сможет скачать недостающие зависимости. После подготовки кэша можно запускать с `--offline`. Полная инструкция: [Сборка AnimaDev из исходников](BUILD_FROM_SOURCE.md).

## 4. Подключить локальный проект в AnimaDev

1. Откройте **Termux → Проверить окружение**.
2. Добавьте существующий Git-каталог через вкладку **Проекты**.
3. Убедитесь, что выбран правильный `origin`, текущая ветка и локальные изменения.
4. Выполняйте только поддерживаемые действия Git и Gradle. `UNKNOWN` означает неопределённый результат — используйте повторную проверку **того же задания**, а не новый запуск.

Для инструментальных тестов отдельно понадобится разрешённая ADB-связь с устройством.

## 5. AnimaBridge Agent — необязательная отдельная служба

**Не устанавливается автоматически.** Если вы уже отдельно установили AnimaBridge Agent и хотите управлять им из AnimaDev:

1. Установите менеджер служб Termux: `pkg install termux-services`, затем заново откройте Termux, чтобы активировать `runit`.
2. Убедитесь, что каталог **действительно установленного** агента содержит `termux_agent/__main__.py`.
3. Из исходников AnimaDev ознакомьтесь со скриптом [`scripts/install_animabridge_service.sh`](../scripts/install_animabridge_service.sh). Он регистрирует службу **в остановленном состоянии** и не должен перезаписывать уже зарегистрированную.
4. **Не запускайте службу поверх ручного агента.** Сначала безопасно завершите ручную копию, только потом используйте AnimaDev → Termux → AnimaBridge → **Запустить**.
5. Для диагностики в Termux: `sv status animabridge`. Для явной остановки / запуска используйте кнопки AnimaDev либо штатные команды `sv`.

После подтверждённого «Запустить» AnimaDev снимает флаг `normally down` для постоянного автозапуска runit; «Остановить» возвращает его. Перезапуск доступен только работающей службе. Плитка и виджет Android управляют той же зарегистрированной службой, не создавая второго агента. **Запущенный Python-процесс не равен подтверждённой связи с сервером.**

## 6. Shizuku — необязательно

В **Termux → Shizuku** можно запросить разрешение и проверить Binder-соединение с отдельно запущенным Shizuku. Сейчас это **диагностика**, а не способ запускать Python внутри приватного каталога Termux. Для Git/Gradle или управления `runit` Shizuku не нужен.

## 7. Безопасность и неполадки

- Не размещайте JKS, пароли, токены, приватные ключи или логи с персональными данными в GitHub и общих «Загрузках».
- Не очищайте `~/.gradle` и SDK для исправления обычного сбоя подключения.
- Termux после принудительной остановки Android может запрещать фоновый запуск, пока его не откроют вручную.
- Если `RUN_COMMAND` не проходит, сначала проверьте разрешения и Termux, а не запускайте второго агента.
- Никаких официальных APK в GitHub Releases пока нет. Собрать приложение самостоятельно можно по [отдельной инструкции](BUILD_FROM_SOURCE.md).
