# Godot Android в AnimaDev — рабочий план ветки `godot_Android`

**Статус:** исследование и проектирование; **не** означает готовую поддержку экспорта/редактирования Godot. Базовый `main` — проверенная версия AnimaDev dev.47, объединяющая GitHub-first и интерфейс Shizuku.

## Цель

AnimaDev должен автоматически обнаруживать тип локального Git-репозитория и показывать инструменты, соответствующие **технологиям проекта**, без чужих Gradle-кнопок и жёсткой привязки к `animaquiz`. Первый новый профиль — **Godot Engine → Android**. В дальнейшем профильная модель позволит добавлять Android/Gradle, Godot, веб и смешанные репозитории.

## Текущее положение

- Каталог в `app/src/main/assets/catalog/catalog.py` безопасно ищет локальные репозитории и worktree в Termux, ограничивает глубину и не следует по symlink.
- `ProjectTools.kt` имеет общий экран со статусом Git, но блок действий рассчитан на Gradle/AnimaQuiz и `project.supported`; неподдерживаемые проекты показываются только для чтения.
- `RepoGateway.kt` имеет жёстко заданный `PROJECT = "animaquiz"`, а runner и журналы ориентированы на этот профиль. Не использовать одну и ту же Job/Project ID для разных репозиториев.
- Через AnimaBridge 3.1 доступны безопасные команды Termux, фоновые jobs и Shizuku; **само приложение AnimaDev не должно становиться зависимым от Render**. Оно продолжает работать напрямую через Termux RUN_COMMAND.

## Фаза 1. Автоопределение типа проекта (сначала read-only)

Проверять **содержимое корня репозитория**, не его имя/remote URL:
- `project.godot` → `GODOT` (считать версию/рендерер только после безопасного разбора настроек);
- `settings.gradle(.kts)` / `build.gradle(.kts)` / `gradlew` → `ANDROID_GRADLE` при подтверждённой Android-конфигурации, иначе `GRADLE_GENERIC`;
- `package.json` → `JS` / `WEB` (по безопасным маркерам фреймворка, при недостатке данных `UNKNOWN`);
- несколько уверенных маркеров в одной репозитории → `MIXED` с несколькими профилями, не подменять тип догадкой;
- отсутствие маркеров → `UNKNOWN` с Git/файлами только для чтения.

Сканирование ограничено разрешённым корнем, количеством файлов, временем и размером конфигов; не открывает `.git`, `.godot`-кэш, keystore, `.env` и системные пути. Не разыменовывать символические ссылки. Игнорировать вложенные `node_modules`, `build`, кэши и чужие Git worktree. Вложенные проекты учитывать как отдельные подпроекты только по явному безопасному правилу.

Новый ответ каталога содержит `project_type`, `detected_markers`, `confidence`, `capabilities`, `subprojects` и `detection_errors`; неизвестные enum или частичные данные не открывают опасные действия. Пользователь может явно выбрать тип, но при несовпадении маркеров запуск сборки остаётся заблокирован до проверки.

## Фаза 2. Профили и динамический интерфейс

Разделить:
- общие возможности: GitHub-first состояние, ветки, worktrees, статусы, поиск, история и безопасные задания;
- Android/Gradle: unit/device tests, APK/AAB, `adb`, готовые пайплайны;
- Godot: версия движка, `project.godot`, список сцен/скриптов/ресурсов, диагностика Godot CLI, профили Android-экспорта, экспорт APK/AAB, установка и лог запуска;
- mixed: выбор проекта/подпроекта и контекстные инструменты, не смешивая каталоги и журналы сборок.

Компоненты экрана регистрируются через явные `capabilities`, а не цепочки проверок имени репозитория. Приложение сохраняет последнее выбранное представление для каждого `project.id`. Показать тип, точное основание распознавания и кнопку «Переопределить» / «Повторно определить».

## Фаза 3. Godot на телефоне — диагностика и экспорт Android

Вначале диагностика среды **без установки пакетов по умолчанию**:
- `godot --version`, сведения о headless-режиме и поддерживаемом CLI;
- расположение Godot Android export templates и совместимость версии;
- JDK, Android SDK / build-tools, Gradle, ADB и доступное место;
- список **имён** Android export presets; пароли, подписи, пути к keystore, токены и `export_presets.cfg` целиком в UI/журналы не выводить.

Операции поэтапно:
1. безопасная read-only проверка `project.godot` и export preset;
2. запуск Godot в headless editor/import и контролируемая проверка проекта;
3. `--export-debug` в **выбранный выходной путь** с контролем Job ID, времени и SHA-256;
4. release `APK` / `AAB` только при настроенных export templates, Android SDK и защищённых настройках подписи; никакого создания/вывода паролей в командах или логах;
5. установка готового APK и инструментальная диагностика через текущий Termux или опциональный Shizuku (не обязательный для самого экспорта).

Godot Android экспорт **не всегда** равен прямому Gradle build: приложение должно выбирать поддерживаемый Godot CLI-пайплайн и проверять результат по артефакту, а не копировать Gradle-команды из Android-профиля.

## Фаза 4. Тесты и приёмка

- Fixtures: Godot 3/4, Godot 4 Android, обычный Gradle/Android, generic Gradle, JS, monorepo с Godot/Android, пустой и ошибочный Git repo, worktree.
- Безопасность: symlink за пределы разрешённой папки, слишком большой конфиг, поддельный `project.godot`, неверный preset, `export_presets.cfg` с чувствительными полями, конфликт Job ID, грязный Git и отказ разрешений.
- UI Compose: автоопределение, смешанные профили, скрытие несовместимых инструментов, сохранение выбора, малая ширина, крупный шрифт, светлая/тёмная тема.
- Termux: read-only диагностика → headless check → debug APK export → install/test на **том же Realme**; никакого перезаписывания пользовательских проектов.
- Git: только отдельные ветки и worktree. `main` остаётся стабильным, отдельный PR на каждую готовую фазу.

## Критерии первой версии

Первая версия признаётся готовой, когда AnimaDev автоматически различает Godot и Android Gradle по файлам, не путает monorepo, показывает профильные инструменты, проверяет доступность Godot CLI, умеет экспортировать **реальный Android debug APK** из тестового Godot-проекта в изолированной директории и даёт понятные статусы/журналы по Job ID. Release signing и AAB — отдельный этап после уверенного debug-процесса.

**Не делаем:** автоустановка SDK/Godot без согласования, чтение ключей подписи, сброс Git, дублирование AnimaBridge в приложении, зависимость от Render.
