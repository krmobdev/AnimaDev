# AnimaDev — этап 3А, контрольная точка 09.10.2026

Исходный AnimaDev: feature/termux-probe, e7c6dfd, дерево чистое.
Этап 2.1 принят владельцем: обновление APK, сохранность Git/журналов, отмена
и finishAndRemoveTask проверены на Android. Этап 3А ещё ждёт Android-приёмки.

## Артефакт

APK в «Загрузках»: `AnimaDev_0.3.0_tests_debug.apk`.
Версия 0.3.0-tests, versionCode 4, размер 11 602 492 байт.

Подпись v2 действительна; сертификат совпадает с принятой 0.2.1:
`dcc04062e9d1cf6bbd8c0f897d77fe4635f76451c2a04691e2e0f3c4d9cc40ea`.
Package ID остаётся com.animacode.animadev, versionCode 3 → 4.
Точные байты обоих модулей в APK совпадают с исходниками и SHA-256 assets;
хеш helper связан с проверенным основным runner. Хеш копии Downloads совпадает.
Обновлять поверх текущего приложения, не удаляя его.

## Реализовано

«Запустить тесты» запускает только фиксированную команду в ~/quizapp:

`bash ./gradlew :app:testDebugUnitTest --offline --no-daemon --rerun-tasks --console=plain`

Проверяются разрешённая ветка test/decomposition-v1, origin и каталог.
TEST делит блокировку с Git. UI работает асинхронно, хранит ID/состояние,
QUERY уточняет существующее задание без повторного START. Статусы ожидания,
выполнения, успеха, ошибки и UNKNOWN отделены. Последние результаты TEST
сохраняются отдельно и не теряются при следующей Git-операции.

Успех требует exit 0 и новых валидных JUnit XML без провалов. Показаны реальные
счётчики total/passed/failed/skipped, сумма времени JUnit и длительность операции.
Старые XML игнорируются по отпечаткам inode/mtime/ctime/SHA. Нет отчётов,
ошибка парсинга или процесс только запущен — не успех. Диагностика ограничена,
распознаваемые секреты маскируются, многострочные приватные ключи подавляются
с сохранением состояния фильтра, кадры трассировок отфильтрованы.

Добавлены короткие объяснения кнопок, повторов и блокировок. «Связь Termux»
объяснена как диагностика, необязательная перед каждым действием. В документации
зафиксированы будущие «Мои проекты» / «Диагностика», без редизайна сейчас.
Новые токены, серверы, runtime-зависимость от AnimaBridge отсутствуют.
APK QuizApp, несколько проектов и этап 3Б не реализованы.

## Ограничения и непроверенное

- Установка 0.3.0, загрузка двух модулей помощника, реальный TEST QuizApp через
  Android UI, его callback и восстановление при закрытии/force-stop нового APK
  пока не проверены на устройстве. Это приёмка владельца, не результат компиляции.
- Старые immutable releases 0.2.0/0.2.1 сохранены для незавершённых QUERY;
  выбор версии проверен политиками, Android-переход с активным job требует проверки.
- Таймаут Gradle 20 минут. Его собственная основная группа останавливается,
  но отдельная одноразовая JVM может остаться; поэтому timeout/потеря контроллера
  дают UNKNOWN и блокируют проект. Автоматического сброса/повтора в этой версии нет.
- Логи SQLite ограничены 4096 символами на канал, callback 1500 на канал;
  строки более 8192 байт пропускаются; остаток этого канала скрывается,
  чтобы не показать продолжение возможного секрета. История имеет прежний лимит 100 заданий.
  Поэтому диагностика является кратким журналом, не полным неограниченным логом.
- JUnit: до 500 файлов, 2 MiB каждый и 8 MiB суммарно. Неподдерживаемый или
  повреждённый отчёт не заменяется выдуманной статистикой.
- Gradle требует существующих Java/wrapper/офлайн-зависимостей. В проекте
  выполняются его согласованные Gradle-скрипты и тесты; runner не редактирует
  исходники, но Gradle обновляет build/.gradle/кеш. Не запускать внешний Git/Gradle
  параллельно. Незакоммиченные исходники допустимы: тестируется рабочая копия.
- Полный разрыв сети телефона/убийство JVM Android и реальный 20-минутный таймаут
  не испытывались end-to-end; короткие изолированные сценарии состояния проверены.

## Приёмка — только через кнопки

1. Установить новый APK поверх 0.2.1 из «Загрузок», без удаления приложения.
2. Открыть «Репозитории». Завершить уточнение прежнего задания, если оно активно.
3. «Настроить локальный помощник» → «Настроить», затем «Обновить состояние».
4. Проверить AnimaQuiz и test/decomposition-v1; нажать «Запустить тесты» один раз.
5. Во время работы проверить блокировку Git и повторного TEST, открыть подробности
   и записать Job ID. Повернуть экран, выйти с подтверждением и открыть приложение.
6. Проверить тот же ID и результат. При задержке callback нажать «Уточнить состояние»;
   это не повторный запуск. Статистика появляется только после новых JUnit XML.
7. Проверить код завершения, total/passed/failed/skipped, время JUnit и общую
   длительность. При ошибке прочитать объяснение и ограниченную диагностику.
8. После подтверждённого завершения TEST можно повторить отдельно. CHECK тоже
   можно повторять после завершения. SYNC требует отдельного подтверждения и
   безопасного ff-only; автоматически после тестов он не запускается.

После контрольной точки работа остановлена до Android-приёмки. Этап 3Б не начат.

JVM-тесты выполнены в первой сборке, финальная упаковка использовала их актуальные
UP-TO-DATE результаты; XML проверены повторно итоговым parser. Финальный runner
проверен новым реальным Gradle fixture после изменения защиты логов.
