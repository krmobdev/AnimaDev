# AnimaDev — дорожная карта локальной сборки и доставки

## Неизменные правила

- **GitHub — единственный источник истины для исходников.** AnimaDev только проверяет соответствие SHA, читает Git-метаданные и по явному действию получает обновления в Termux. Никаких push, merge, dispatch GitHub Actions, создания коммитов, запуска удалённых сборок или автоматической смены ветки.
- Сборки APK/AAB выполняются **только локально в Termux**, с текущей явно выбранной ветки после проверки origin, чистого рабочего дерева и равенства SHA. Недоказанное состояние — блокировка.
- Одна Gradle-сборка на всё устройство: единый локальный слот и общий межпроцессный файловый lock для всех проектов и режимов Debug/Release. При `UNKNOWN` нельзя автоматически стартовать повторно.
- APK/AAB доставляются в Android «Загрузки» либо явно выбранную SAF-папку (после проверки доступа). Готовый файл показывается с проектом, веткой, коммитом, размером, SHA-256 и результатом проверки подписи.
- Секреты JKS никогда не отправляются в GitHub, не попадают в Intent, shell argv, историю команд, журналы, SharedPreferences или рабочую папку. Release использует локальный Unix-сокет с проверкой UID и память Termux.
- Пользовательские исходники, Git worktree, история задач и ключи не очищаются, не сбрасываются и не заменяются автоматически.

## Этап 1 — надёжный диспетчер сборок (текущий)

- Единая блокировка Debug/Release и межпроектных запусков в Android и Termux.
- Экран «Сборка»: активный проект, тип задания, состояние, время, настоящий текущий этап, доступ к журналу, причина блокировки каждой кнопки.
- Освобождение слота только по подтверждённому терминальному результату. Для недоступного/неподтверждённого процесса — «Проверить состояние», а не слепой повтор.
- Регрессии: два запроса в один проект, два проекта, Debug против Release, отказ Termux, неизвестный итог, восстановление после убийства Activity.

## Этап 2 — единый монитор прогресса

- Одна модель BuildJob для Debug APK, Release AAB, тестов, проверки/синхронизации Git.
- Монотонные безопасные стадии: Git SHA → подготовка Gradle → компиляция → упаковка → подпись/верификация → доставка.
- Передача стадий Release из Termux отдельным несекретным каналом с проверкой ID, а не имитация процентов.
- Внутри окна сборки — последние строки **санитизированного** журнала, реальное время последней активности, уведомление о завершении.
- Восстановление после перезапуска приложения и проверка по ID без повторного запуска.

## Этап 3 — доставка файлов

- Выбор Загрузки или SAF-папка, надёжное восстановление permission grant.
- История файлов проекта: версия, SHA Git, дата, тип, размер, SHA-256, подпись.
- Открытие Android Sharesheet для готового файла через FileProvider/SAF; без публикации через GitHub.
- Безопасное именование файлов; при коллизиях не заменять существующее без явного подтверждения.

## Этап 4 — несколько проектов

- Профиль сборки из проверенных Gradle-модулей, целевого applicationId, задач debug/release.
- Список проектов с указанием локального Git-состояния и текущей/последней сборки.
- Очередь **не автоматическая**: пока идёт одна сборка, остальные действия только ожидают явного запуска после завершения.
- Отдельные история/папки назначения/сертификаты каждого проекта.

## Этап 5 — UX и приемка

- Экранная структура: проект → Сборка → прогресс → результат → Поделиться/Открыть.
- Действия «Проверить GitHub SHA», «Обновить из GitHub» (только разрешённый fast-forward), «Собрать», «Посмотреть лог».
- Проверки устройства для выбора ветки, повторного входа, фоновой сборки, подписи JKS и доставки после смены папки.
- APK выдавать только после Gradle тестов, проверки cert SHA-256, версии, SHA-256 файла, совпадения с commit GitHub.

## Критерий готовности

Нажатие «Собрать» подтверждает **один** локальный Gradle-процесс. Пользователь видит проверяемый прогресс и результат на том же экране; другие сборки заблокированы до подтверждения завершения. GitHub не используется как удалённый исполнитель.
