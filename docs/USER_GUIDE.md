# AnimaDev — руководство пользователя

## Ветки GitHub в dev.46
GitHub — источник правды. На экране **«Ветки»** нажмите **«Обновить origin с GitHub»**, затем выберите ветку. Ветка, присутствующая только в origin, будет создана локально как отслеживающая; существующая локальная ветка может быть обновлена только fast-forward. Перед операцией Termux повторно сверяет SHA GitHub и origin, чистоту дерева и текущий HEAD. Разошедшиеся ветки, локальные ветки без GitHub и незакоммиченные файлы не переключаются, никакого reset или удаления нет.


## Git и ветки в dev.45
Если Git показывает `CHECK · UNKNOWN` с сообщением об исчерпании 100 заданий, откройте раздел Git/Тесты, нажмите **«Обновить локального помощника»**. Новый runner 0.4.1 принимает до 10 000 заданий без удаления старой SQLite-истории. Затем нажмите **«Проверить статус в Termux»** для исходного Job ID. Если операция действительно не запускалась, появится подтверждённое состояние «Не запускалась», после которого можно выполнить новую проверку Git. Не очищайте вручную папку `.local/share/animadev`.
Локальные ветки без origin не доступны для переключения в GitHub-first режиме. Удалённые ветки GitHub можно выбрать даже без локальной копии после обновления origin.


## Новое в dev.44
Запуск Debug APK, Release AAB, unit- или инструментальных тестов автоматически прокручивает экран до текущего задания. Во время Release AAB показываются текущая нагрузка процессов Termux по всем ядрам, доступная/занятая оперативная память и использование zRAM; данные обновляются примерно каждые 5 секунд. Кнопка **«Проверить»** в Shizuku работает без блокировки интерфейса, рядом отображаются индикатор и пинг Binder (мс).

## Shizuku в dev.43
Откройте вкладку **Termux → Shizuku**. Если служба Shizuku уже запущена, приложение определит её напрямую через Binder. Нажмите **«Разрешить доступ»** и подтвердите запрос в Shizuku. После этого появится статус **«Подключено»**, API-версия и системный UID (обычно **2000 / shell** при запуске через беспроводную отладку). **«Проверить»** обновляет состояние, **«Открыть Shizuku»** ведёт к настройке службы. AnimaDev не запускает службу и не выдаёт разрешения самостоятельно. Соединение с Shizuku работает без VPN, Render и обязательного `adb connect`. Пока это этап подключения и диагностики; выполнение системных действий через Shizuku будет отдельным этапом.


## Обновления интерфейса dev.41
Закрепление: на карточке репозитория откройте меню «⋮» → «Закрепить сверху». Это меняет только порядок карточек в AnimaDev.
Ветки: можно переключать подтверждённые локальные ветки любого зарегистрированного обычного Git-репозитория, если дерево чистое, SHA локальной ветки и GitHub совпадает, и ветка не занята другим worktree. Если ссылки origin устарели, нажмите «Обновить origin с GitHub» — безопасный fetch обновит только remote-tracking refs. Reset, merge, force, prune и удаление файлов не выполняются.
Сборки и тесты: после запуска экран прокручивается к карточке задания. Release AAB показывает безопасные этапы Gradle; журнал можно переключать между «ВСЕ» и «ВАЖНОЕ». Ключи и пароли не попадают в журнал.
Пароль JKS открывает хранилище; пароль ключа указывается отдельно, если отличается. «Сохранено в Android Keystore» не значит «проверено»: окончательная проверка ключа происходит при подписи AAB в Termux.


## Назначение
AnimaDev — Android-приложение для работы с локальными Git-репозиториями в Termux. Оно показывает ветки, проверяет соответствие GitHub SHA, запускает разрешённые тесты и сборки, хранит журналы. Команды исполняются локально в Termux, а установка собранных APK открывает **системный установщик Android**.

## Состояние Git и локальные изменения
Одинаковые SHA коммитов на телефоне и GitHub **не означают**, что рабочее дерево чистое. Изменённые или новые файлы существуют отдельно от истории коммитов. Git покажет их имена и не будет автоматически делать reset, commit или push. Получение коммитов допускается только с безопасным fast-forward и чистым рабочим деревом. Раздел «Ветки» перечитывает локальные ссылки origin, а реальный GitHub SHA проверяется в разделе Git.

## Где искать работу агента в отдельной ветке
На экране проекта основные инструменты («Git», «Тесты», «Сборка», «История») всегда находятся выше блока «Рабочие каталоги». Этот блок по умолчанию свёрнут: видны только текущая ветка, число других каталогов и кнопка обновления. Нажмите «Показать каталоги», чтобы развернуть список, и «Скрыть список», чтобы снова его свернуть. Для обновления нажмите значок обновления в заголовке. AnimaDev безопасно читает основную папку и связанные Git-worktree, показывает путь, имя ветки, коммит и локальные изменения. Для подробностей нажмите на карточку и скопируйте путь. **Это только локальные данные Termux.** Проверка отправки на GitHub выполняется отдельно. Изменения в другом worktree не показываются в состоянии основного main, но это не означает, что они пропали. Приложение не удаляет, не коммитит и не переключает другие worktree автоматически.

## Первое подключение
1. Установите Termux из доверенного источника, откройте его хотя бы один раз.
2. Разрешите интеграцию `RUN_COMMAND` через настройки Termux; AnimaDev не включает её самостоятельно.
3. Откройте вкладку «Termux» в AnimaDev и нажмите «Проверить окружение».
4. Воспользуйтесь кнопкой «Подготовка сборки» для подробной последовательности установки инструментов.
5. Укажите существующий локальный Git-репозиторий в разделе «Проекты», проверьте ветку, чистоту и GitHub SHA.

## Git и проекты
Проверка SHA сверяет локальный HEAD с разрешённой удалённой веткой. Синхронизацию разрешено делать только явно и в режиме fast-forward. AnimaDev не выполняет автоматический push, force или уничтожение изменений. Worktree в зависимости от профиля может быть доступен только для просмотра.

## Тесты и журнал
«Unit-тесты» используют Gradle для локальной проверки кода, «На устройстве» — инструментальные тесты через настроенный ADB. Запущенное задание имеет ID и журнал. После закрытия экрана возвращайтесь к тому же ID: «Проверить состояние» не запускает новый процесс. Остановка доступна только для поддерживаемых типов заданий.

## Debug APK
1. Сверьте GitHub SHA и отсутствие локальных изменений.
2. Выберите папку сохранения в настройках «Файлы и загрузки» (основная память устройства; иначе вернитесь к «Загрузкам»).
3. Нажмите «Собрать Debug APK · полная пересборка». Используется `--rerun-tasks`, без удаления Gradle-зависимостей.
4. Для установки откройте готовый APK: файл проверяется по SHA-256, передаётся Android Package Installer через `FileProvider`. При необходимости один раз выберите APK в системном проводнике и дайте разрешение Android на установку из AnimaDev.
5. «Очистить временный кэш AnimaDev» удаляет только копии APK и экспортированные временные отчёты в кэше приложения. История и настройки остаются.

## Release AAB
Для публикации нужен JKS и alias. Пароль обрабатывается с локальным защищённым обменом и не должен попадать в GitHub, журналы или аргументы команд. AAB не устанавливается обычным нажатием на Android; откройте папку готового AAB и публикуйте его через соответствующую платформу. Историю и детали смотрите во вкладке «История».

## Скины
Новый скин Emerald Glass выбирается в «Настройки → Внешний вид» независимо от Pulse и по умолчанию выключен. Он использует тёмные графитовые карточки и зелёные акценты. Проекты, Git, тесты, сборки, история и выбранная папка сохраняются при переключении. Дополнительно оформлены Tests, History, Branches, Termux, Settings и About; журналы и процессы сохраняют прежнюю логику. Монитор заданий, журналы и вложенные настройки также получили новый стиль. В Emerald Glass вместо меню с тремя точками нажмите шестерёнку: в настройках находятся «Список изменений», «Документация» и «О программе». Кнопка «Назад» возвращает к прежнему инструменту. На маленьком экране вкладки могут прокручиваться горизонтально, а нижняя навигация располагает иконку над подписью при увеличенном шрифте. Визуальная проверка на устройстве необходима. Сырые журналы, SHA и пути остаются без переводов.

## Язык
В «Настройки → Внешний вид → Язык / Language» доступны «Как в системе», «Русский» и «English». Подписи кнопок, состояния и диагностические сообщения переводятся. Сырой журнал команд Git/Gradle остаётся в оригинале, а SHA, пути и Job ID не изменяются.

## Что делать при ошибке
- **SHA не совпадает:** выполните проверку Git; не обходите блокировку грязного дерева.
- **Зависимости недоступны:** проверьте Android SDK, JDK 21, Termux и кэш Gradle. Для первого получения зависимостей может понадобиться интернет.
- **Задание UNKNOWN:** откройте журнал и уточните состояние старого ID; не начинайте второе задание поверх неизвестного.
- **APK не устанавливается:** убедитесь, что выбрали именно этот файл и разрешили системную установку из AnimaDev.
- **Папка недоступна:** выберите основной накопитель или сбросьте папку на «Загрузки».

## Сохранность данных
Не удаляйте Termux или каталоги Git для очистки кэша. Очистка кэша AnimaDev не удаляет проекты, задания, SQLite, JKS и пароли.

## Управление AnimaBridge через AnimaDev (dev.48)

Экран **Termux → AnimaBridge** управляет заранее зарегистрированной службой `animabridge` с кнопками «Проверить», «Запустить», «Остановить», «Перезапустить». Сначала выполнить однократную регистрацию по инструкции «Подготовка Termux», затем остановить старый агент, если тот был запущен вручную. Кнопки используют `sv` через Termux RUN_COMMAND, а не путь к Python-агенту. Приложение не устанавливает службу самостоятельно и не хранит ключи подключения.
