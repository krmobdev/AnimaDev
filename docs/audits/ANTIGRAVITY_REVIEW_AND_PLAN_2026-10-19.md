## План и критерии

1. Исправить подтверждённые пользовательские ошибки без изменения канала подписания или git-операций.
2. Ввести регрессионные JVM/Python/Android fixture тесты, проверку SHA и сборку на отдельной ветке.
3. Зафиксировать реальный тестовый результат; ошибки существующих тестов проверять отдельно на main.
4. Предложить PR на main без слияния — **слияние только после разрешения владельца**.

## Ограничения

- Безопасные durable commit в ключевых переходах Release и переключения веток намеренно сохранены. Для полного устранения синхронного I/O требуется проектирование и инструментальный тест goAsync/потоков/восстановления после kill.
- Не запускать производство APK с новыми versionCode до отдельного решения о релизе.
