# beta.6: границы и модель представления

SettingsPolicy индексирует существующие настройки и честно обозначенную информацию. Семь компактных разделов, поиск по названию/описанию, возврат к сохранённому запросу. Сохранены пространства и ключи interface_v1, monitor_settings, files_v1; миграции и очистки SQLite/SharedPreferences нет. SAF grants и выбранный URI не изменяются при обновлении.

JournalPresentation фильтрует только представление IMPORTANT. ALL, исходные страницы SQLite, порционные курсоры и журналы Termux не переписываются. Команды раскрываются визуально, поиск/копирование/экспорт используют исходный доступный очищенный текст. Длительность операции и сумма JUnit-time обозначены отдельно.

Каталог читает фиксированную for-each-ref без общего лимита количества веток. Страница — до 32 refs плюс максимум две закреплённые записи, до 16000 bytes; поток ограничен двумя секундами, строка 2048 bytes. Ограничение ресурса вызывает явную ошибку, а не тихое усечение. Чтение следующих страниц использует offset; старый вызов BRANCHES без offset поддерживается. Ответ проверяется по request ID, пути и ожидаемому offset. При изменении refs во время чтения список следует обновить; это локальные сведения без сетевого fetch. Local/origin объединяются по имени, обе SHA сохраняются. Статус совпадения SHA не означает актуальность GitHub.

Неизменная дорожная карта приложения: GitHub — источник версий, Termux — Git/Gradle-исполнитель, AnimaDev — автономный интерфейс без токенов и GitHub API. Будущая последовательность: получить данные GitHub через fetch, безопасно привести выбранную локальную ветку к точному SHA, проверить SHA, тестировать/собирать именно его. Полное переключение веток и сборки других проектов относятся к этапам B/C. Это отличается от регламента агента, который уже публикует изменения через GitHub-коннектор и синхронизирует Termux перед проверками.
